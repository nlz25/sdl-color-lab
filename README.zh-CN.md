# SDL Color Lab

[English version](README.md)

用于本地实物配色实验，包含 **React 前端**、**Python／FastAPI 后端**及 **Opentrons OT-2 协议**。实验员在网页、OT-2 App 和酶标仪之间交接文件、转移微孔板；网页负责生成配方、将实测吸收光谱转换为 sRGB，并记录 **CIEDE2000 色差（ΔE₀₀）**。

**每次实验固定一个模型，共六轮。** 开始前选择 GPT-6 或 BO-EI，启动后不能切换；测试另一模型请新建实验。比较两种模型时，在两个实验中使用相同目标与工作液。每种方法每轮只有一个候选、一个孔，红、绿、蓝和水合计 **200 µL**。GPT 使用 **A1–A6**，BO 使用 **B1–B6**。无需基色标定，两种方法均不接收基色实测 RGB、Lab 或光谱；保留试剂名称与目标色，仅使用各自的实测历史。

GPT 首轮直接推理配方。BO 首轮用固定 **seed 0** 可复现地探索，此时不拟合模型；第 2–6 轮用 BO 自己的结果拟合 GP，使用以 LogEI 实现的 EI。首轮探索计入六轮预算，不增加额外实验。**成功标准为 ΔE₀₀ ≤ 1**，包含恰好等于 1；即使提前成功仍完成六轮。

## 1. 安装与启动

### 首次从 GitHub 获取项目

下载或克隆仓库后，在项目根目录打开终端。安装 Python 3 和用于首次构建的 **Node.js 22.12 或更新版本**，执行一次：

```sh
# macOS
python3 scripts/build_frontend.py
```

```bat
:: Windows
py -3 scripts\build_frontend.py
```

脚本按照 `frontend/package-lock.json` 安装依赖并生成 `frontend/dist/`。构建产物不提交 Git，因此从 GitHub 新下载的源码需要先构建；修改前端源码后也要重新构建。已经包含 `frontend/dist/index.html` 的本地副本可以跳过此步。

### 启动实验

1. 使用 GPT 时，先将根目录 [.env.example](.env.example) 复制为 `.env`，按下文填写模型配置；BO-EI 无需填写。
2. macOS 双击 [start_macos.command](start_macos.command)，Windows 双击 [start_windows.bat](start_windows.bat)。首次启动需要联网安装锁定的 Python 依赖，包含 **Opentrons 9.0.0** 和 **NumPy 1.26.4**；统一使用后端的同一个环境，支持 Python **3.10–3.12**。
3. 保持启动窗口打开，浏览器自动进入 **http://127.0.0.1:8501/**。构建后的页面日常运行不需要 Node.js。

需要更换端口时，macOS 执行 `python3 scripts/launch.py --port 8502`，Windows 执行 `py -3 scripts\launch.py --port 8502`。使用启动器打开的完整地址。

页面默认**英文**，右上角 **EN / ZH** 可切换，当前上传和实验进度保留。刷新后恢复英文。实验下拉列表以当前所选方法为前缀：**BO-EI** 或配置的 GPT 模型 ID。

## 2. 准备正式实验

**模型配置。** 使用 GPT 时，将同目录 [.env.example](.env.example) 复制为 `.env`，填写 `OPENAI_API_KEY`、实际可用的 `OPENAI_MODEL`；使用兼容接口时另填 `OPENAI_BASE_URL`。修改后重启服务。Finder 按 **Command + Shift + .** 显示隐藏文件。首次选择 GPT 时，页面自动检查模型连接；BO 无需密钥，也无需先连接 GPT。GPT 模型标识和接口地址在创建实验时固定，变更时请新建实验。

Initial prompt 和 feedback prompt 均使用**英文**，不随页面语言切换。新请求要求用英文解释配方理由；此前已归档的请求和回复保留原文。

**准备工作液。** 准备红、绿、蓝工作液及纯水，将品牌／批次及稀释倍数记录并交给主办方。不再制备或上传基色标定孔。各轮候选保持相同板型、**200 µL** 体积、酶标仪设置和背景处理方式。

设置目标色即可开始，仅在候选配液、测量后上传该候选的光谱。页面按上传的吸光度直接转换，不自动扣空白。

**光谱格式。** 每份 UTF-8 CSV 只含一条光谱、两列数据：

```csv
Wavelength(nm),OD Value
380,0.1728566485933389
381,0.17839566290272532
```

以上仅示意格式。完整文件必须覆盖 **380–780 nm**，波长递增、不重复、间距不超过 **10 nm**，吸光度为有效非负数；1 nm 扫描与现有案例一致。也支持表头 `wavelength_nm,absorbance`。完整案例见 [base_Blue.csv](backend/src/sdl_color_lab/resources/data/base_Blue.csv)，红、绿案例在同一文件夹。

当前页面使用这一 CSV 格式。主办方如提供其他导出格式，先取得真实样例，再适配后上场。

**开始。** 选择 **GPT-6** 或 **BO-EI**，设置目标 RGB（默认 **143,150,106**），点击**开始 [所选方法] 六轮**。实验编号与候选孔位自动分配，模型与初始设置随后固定。恢复旧实验时保留当前模型、原标定、配方与历史。

## 3. 首次配置 OT-2

将项目放在操控 OT-2 的同一台本地电脑，完成上面的首次安装后，双击根目录的 macOS／Windows 启动器打开网页。另外安装并打开 **[Opentrons OT-2 App](https://opentrons.com/ot-app)**；安装 Python 包不会自动安装这个桌面软件，也不会自动连接机器人。操作 App 期间保持网页的启动窗口打开。

机器人由 **Opentrons OT-2 App** 控制，网页通过 CSV 交接。该电脑通过以太网或已配置的局域网连接 OT-2，在 **Devices** 中选择机器人。

在初始化或实验页面点击**下载脚本 · 仅需一次**，保存 `SDL_CSV_protocol.py`，再通过 **Protocols → Import** 导入。同一文件也位于项目的 [opentrons/SDL_CSV_protocol.py](opentrons/SDL_CSV_protocol.py)。机器人软件须支持 **Protocol API 2.28**。按 App 的分析结果核对实物布局，完成移液器和耗材偏移检查。

Python 协议规定移液器、原料位置、移液动作和混匀，全部轮次复用这一份。CSV 提供本轮孔位和各组分体积，脚本通过 App 的 **Recipe CSV** 参数读取其内容。修改协议后须重新导入并分析。网页启动器只启动页面，每轮仍由操作员在 OT-2 App 中选择本轮 CSV 并开始设备运行。

| 项目 | 要求 |
|---|---|
| 移液器 | 左侧 `p20_single_gen2`；右侧 `p300_single_gen2`，均为单通道 |
| 槽 4 | `opentrons_96_tiprack_300ul` |
| 槽 5 | `opentrons_96_tiprack_20ul` |
| 槽 7 | `corning_96_wellplate_360ul_flat` |
| 槽 8 | `opentrons_10_tuberack_falcon_4x50ml_6x15ml_conical` |
| 槽 10／11 | 固定 Heater-Shaker 在位，不启用加热／振荡；槽 11 留空 |
| 原料管架孔位 | A3 水、A4 红、B3 绿、B4 蓝，使用四个 50 mL 管位 |

使用两个独立实验比较两种模型时，两种枪头架的前 **60 个位置均须未使用**；合计十二次执行期间保持枪头架在位。协议为每把移液器每次执行预留五个枪头位置。

**配液前必须核对：**当前代码假设每支源管初始 **45 mL**，吸液点距管底 **40 mm**。这是尚未实物验证的继承参数，机器人操作员必须核实液面、枪头可达性和耗材偏移；不匹配时调整协议并重新分析。混匀设置为距孔底 2 mm，**100 µL 一次**，需确认实际板内能混匀。命令行仿真已通过，不能替代现场 App 分析和试配。

## 4. 每个候选重复一次交接

1. **生成：**核对页面上的方法、轮次和孔号，点击**生成配方**。
2. **交接：**配方 CSV 已自动保存在项目中。点击**打开 CSV 文件夹**，在 OT-2 App 的运行参数 **Recipe CSV** 中选择本轮文件，重新分析；核对孔号、执行序号、四种体积和台面后开始运行。Python 脚本只需下载、导入一次，之后复用。
3. **检测：**等待 App 显示完成。协议依次加水、红、绿、蓝，再混匀。保持微孔板方向，将板移至酶标仪，检测当前孔。
4. **上传：**在网页当前轮上传该孔的两列光谱 CSV，核对 RGB／颜色和 ΔE₀₀，点击**确认颜色，完成本轮**。
5. **继续：**生成本次固定模型的下一轮候选。成功标准为 **ΔE₀₀ ≤ 1**，即使提前达到仍完成六轮。测试另一模型时，在实验下拉列表选择**新建实验**，再于开始前选择模型。各实验的配方与测量分别保存。

每次实验在 **`runtime/experiments/<模型_编号>/`** 下只有一个易读的文件夹。里面的 **`opentrons/`** 存放各轮配方 CSV，**`results.csv`** 汇总孔位、配比、RGB 与色差。页面显示准确目录，点击**打开 CSV 文件夹**即可查看；点击文件名仍可通过浏览器另存一份。原始光谱、模型日志和恢复记录放在隐藏的 **`.state/`** 中，**`runtime/.cache/`** 由程序管理；显式配置外部实验目录时采用同样结构。保留完整实验文件夹即可。

CSV **不必与 Python 协议放在一起**：App 通过协议的 CSV 参数传入所选文件。每轮对同一个协议重新开始运行设置，选择新的 CSV。文件名包含模型／方法、轮次和孔号，例如 `gpt-6-astra_R01_A1.csv`（采用本次实验实际 GPT 模型 ID）或 `BO-EI_R01_B1.csv`。脚本读取 CSV 内容，不依赖文件名，内部内容不修改。配方 CSV 交给 OT-2 App，测量光谱 CSV 返回网页。

单条光谱 CSV 不含孔号，操作者必须确认文件确实对应页面显示的当前孔，系统据此绑定本轮。CSV 缺少测量时间时，系统记录**反馈提交时间**，不会将它声称为仪器采集时间。

| 方法 | 方法内部轮次 | 预留枪头分配编号 | 候选孔 |
|---|---|---|---|
| GPT-6 | 1–6 | 1–6 | A1–A6 |
| BO-EI | 1–6 | 7–12 | B1–B6 |

使用网页自动保存的当前轮 CSV。下面仅展示九列接口格式，不是要执行的配方：

```csv
iteration,execution_index,recipe_id,replicate,well,water_ul,red_ul,green_ul,blue_ul
1,7,bo-1-example,1,B1,80,40,30,50
```

每个文件只有一条候选，`replicate=1`，四种体积均为非负整数且合计 200。`execution_index` 用于分配互不重叠的枪头块：GPT 固定为 1–6，BO 固定为 7–12，与实际先后顺序无关。**即使先做 BO，第一轮仍使用编号 7。**下载不代表已配液；重复下载保持相同孔位和枪头分配。

## 5. 恢复、异常与结束

| 情况 | 操作 |
|---|---|
| 浏览器或服务关闭 | 重新启动，在**选择实验**中恢复同一会话，保留项目内的 `runtime/` 数据。 |
| 模型连接或生成失败 | 核对本机配置／网络，重试当前轮；系统不会自动换模型。 |
| 光谱被拒绝 | 核对两列表头、完整波段和数值，上传当前孔的正确 CSV。 |
| 反馈提交中断 | 恢复同一实验，重传同一 CSV，复用原归档和时间；冲突数据不能覆盖已完成轮次。 |
| 机器人只完成部分配液 | 停止，由机器人操作员核对已加体积、已用孔和枪头后安排恢复，**不要直接重跑同一 CSV**。 |

曲线显示逐轮实测色差，**ΔE₀₀ 越低越好**。图下的**逐轮结果**表显示每个已确认候选的模型、轮次、孔位、各组分体积、RGB 颜色和 ΔE₀₀。本次实验的模型固定，预算为**六轮**。实验进行中或结束后，均可使用操作区唯一的**下载实验记录**入口保存 ZIP，其中包含配方、测量、原始文件和模型日志。耗时包含人工交接与测量等待。

主办方负责准备工作液、连接并操作设备、转板及回传光谱；页面操作员负责生成配方、交接 CSV、核对样品与文件对应关系并提交反馈。

## 6. 仓库结构

```text
frontend/       React 页面、交互、图表及 API 客户端
backend/        FastAPI、GPT／BO 算法、光谱转换和实验状态管理
opentrons/      交给 OT-2 App 的独立 SDL_CSV_protocol.py
scripts/        本地启动与前端构建工具
runtime/        本地实验文件夹及程序缓存，不提交 Git
.env.example    配置模板，复制为 .env 后填写本机配置
README.md       英文实验员操作手册
README.zh-CN.md  中文实验员操作手册
```

Git 仓库包含源码、前后端依赖锁文件、配置模板和操作手册。`.gitignore` 排除本地 `.env`、`runtime/` 实验数据、`visuals/` 本地图示、已安装依赖及构建产物。仓库保留 `.env.example`，实际 `.env` 和实验文件夹留在操作电脑上。两份手册均可独立阅读，不依赖 `visuals/`。
